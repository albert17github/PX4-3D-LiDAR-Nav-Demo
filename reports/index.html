Architecture

组件与数据流

项目代码位于组件边界，只负责数据路由、目标接收、路径检查、航点平滑和结果保存；定位、地图、规划与飞控继续使用上游开源实现。

01 / PHYSICS

PX4 + Gazebo

SITL 飞控、动力学、IMU 与 3D LiDAR。

02 / ODOM

DLIO

激光惯性里程计输出 pose、velocity 与 yaw。

03 / FUSION

MAVROS + EKF2

PX4 融合外部位置、机体系速度与航向。

04 / MAP

OctoMap

将 pose + cloud 转为 0.4 m 三维占据地图。

05 / PLAN

MRS 3D A*

MinimalOctomapPlanner 生成完整绕障路径。

06 / GUARD

Safety gate

拒绝不完整路径、越界点和净距不足路径。

07 / EXECUTE

OFFBOARD

平滑航点、到达确认、AUTO.LAND。

Quick start

安装与启动

宿主机依赖清单位于安装文档。项目脚本负责检查、下载固定输入、构建和核验；安装完成后使用 ./demo.sh 启动。

运行时生成在当前 checkout

PX4、DLIO、MAVROS、Ubuntu rootfs 与补丁均有 commit 或 SHA-256 锁；ROS/Gazebo apt 实际版本写入 manifest。默认安装和运行不依赖仓库外的工程目录。

查看完整环境、网络要求和故障定位说明 → 
# Ubuntu 24.04 Desktop / x86_64
git clone https://github.com/albert17github/PX4-3D-LiDAR-Nav-Demo.git
cd PX4-3D-LiDAR-Nav-Demo
./scripts/check_environment.sh --setup
./setup.sh
./demo.sh --interactive
STAGE

明确停在哪一步

输出例如 setup stage 4/6 failed，不把多个下载或构建错误混在一起。

LOG

给出唯一日志路径

每个阶段保存到 runtime/logs/，上游 apt、curl、git 原始错误保持可见。

BOUNDARY

不隐藏环境差异

脚本不自动切换镜像、DNS 或代理，也不绕过非推荐系统；问题处理完成后可继续复用已完成步骤。
